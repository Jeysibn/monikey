## Discovery results and unresolved questions

### Local research downloads

Ten card images were downloaded to `.artwork-research-downloads/`, which is excluded by the root `.gitignore` so research copies are not accidentally committed or served by the app. Nine came from image URLs linked by official issuer pages: four BPI images, Atome Black/Pink/White, the Maya Bukad promotional image, and the classic GoTyme Visa debit image. The tenth is a GoTyme FIFA press photo from The Beat Asia, credited to Visa and GoTyme. All were fetched with ordinary HTTP requests and visually reviewed; the structured inventory records each filename, format, dimensions, and source URL.

The two BPI debit sample images visibly contain a cardholder-like name, expiry, and PAN-like digits; the Platinum Rewards image contains a cardholder-like name. Their authenticity as safe synthetic samples is unconfirmed, so none is suitable for integration yet. The BPI Debit Mastercard, all three Atome design images, the classic GoTyme image, and the GoTyme FIFA press image show no visible cardholder details. Maya's image is a promotion showing the Bukad card in a hand, not an isolated card-face asset. Usage permission remains pending for all ten. These are research copies only: no catalog asset path was assigned, no issuer art is selectable, and none counts as an approved or imported asset.

## Running and extending discovery

Run from `frontend/`: `npm run artwork:discover`, then `npm run artwork:validate`. Discovery reads only the official product URLs in `scripts/card-artwork-seeds.json`, and merges by stable ID so reruns do not duplicate records. Add a product only after confirming its exact name and official page.

To import artwork later, add a repository-local rights JSON record with `artwork_id`, `status: approved`, HTTPS `permission_source_url`, explicit redistribution/application-bundle scope, `evidence_summary`, `reviewed_on`, and `reviewer`. Then run: `npm run artwork:import -- --id <id> --file <local-authorized-image> --source-url <candidate-image-url> --rights <rights-record.json> --privacy-reviewed`. The importer does not fetch remote artwork; it requires a manually reviewed local source file and copies it without altering the design.
